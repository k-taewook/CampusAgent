CampusAgent는 단순 답변형 챗봇이 아니라, 사용자의 자연어 요청을 과제 등록, 일정 조회, 공지 검색, 대학생 정보 추천으로 연결하는 로컬 AI 시스템입니다.

### Slide 02 · 문제 정의 (PROBLEM)

**슬라이드 제목:** 대학생 정보는 여러 도구와 사이트에 흩어져 있다.

**문제 원인 — 5가지 분산 정보원:**

| 정보원 | 담긴 정보 |
|---|---|
| LMS / 메모 | 과제와 제출 정보 |
| 개인 캘린더 | 수업·시험·개인 일정 |
| 학과 홈페이지 | 수업·장학·졸업 공지 |
| 학교 대표 공지 | 학사·등록·행사 안내 |
| 공공기관 / 포털 | 청년정책·공모전·인턴십 |

**결과로 생기는 사용자 부담:**
- 여러 사이트를 직접 방문
- 찾은 정보를 다시 옮겨 적기
- 마감과 조건을 따로 확인

**발표 대본 요점:**
정보를 찾는 일과 관리하는 일이 분리되어 반복 부담이 생깁니다. CampusAgent는 이 5가지 분산 정보를 하나의 대화창으로 통합합니다.

### Slide 04 · 전체 아키텍처 (ARCHITECTURE)

**슬라이드 제목:** LangGraph Agent가 도구와 저장소를 연결한다.

**아키텍처 다이어그램 텍스트 버전:**

```
┌─────────────────────────────────────────────────────────┐
│                    Streamlit UI                         │
│  챗봇 탭 │ 과제 대시보드 │ 캘린더 │ 설정                  │
└──────────────────────┬──────────────────────────────────┘
                       │ 사용자 입력 + 개인화 컨텍스트
                       ▼
┌─────────────────────────────────────────────────────────┐
│              LangGraph Agent (MemorySaver)               │
│   SystemMessage (현재시간 + 전공 + 학년 + 개인화 프로필)   │
└──────────┬───────────────────────────────┬──────────────┘
           │ tool_calls 있음               │ 없음
           ▼                               ▼
┌─────────────────────┐           최종 응답 반환
│      ToolNode        │
│  (총 29개 도구)      │
└──┬──────┬──────┬────┘
   │      │      │
   ▼      ▼      ▼
Task  Calendar  RAG   Student Info
(9개)  (6개)  (5개)   (9개)
   │      │      │       │
   ▼      ▼      ▼       ▼
┌────────────┐  ┌────────────────────┐
│   SQLite   │  │     ChromaDB       │
│ 과제·일정  │  │ 공지·학생정보 검색  │
│ 대화 기록  │  └──────┬─────────────┘
└────────────┘         │
                       ▼
              외부 API / 크롤러
        학교 공지·온통청년·워크넷·K-스타트업
```

**도구 수 강조:**
- Task Tools: **9개**
- Calendar Tools: **6개**
- RAG Tools: **5개**
- Student Info Tools: **9개**
- **합계: 29개**

**발표 대본 요점:**
사용자 입력이 들어오면 LangGraph Agent가 의도를 파악하고, 필요한 도구를 ToolNode를 통해 호출합니다. 각 도구는 SQLite, ChromaDB, 또는 외부 API에 실제 작업을 수행합니다. MemorySaver가 실행 중 대화 흐름을 유지합니다.

### Slide 06 · 과제 관리 — 서브태스크 자동 분해 (TASK)

**슬라이드 제목:** 큰 과제는 자동으로 실행 가능한 단계로 나뉜다.

**과제 도구 9개 목록:**

| 도구 | 역할 |
|---|---|
| `add_task` | 단순 과제 추가 |
| `add_task_with_subtasks` | 큰 과제를 5~7개 서브태스크로 자동 분해 |
| `list_tasks` | 과제 목록 조회 (상태·과목 필터) |
| `list_task_tree` | 부모+서브태스크 계층 구조 조회 |
| `update_task_status` | 과제 상태 변경 |
| `update_subtask_status_tool` | 서브태스크 완료 → 부모 진행률 자동 갱신 |
| `get_task_progress` | 특정 과제 진행률 조회 |
| `delete_task` | 과제 + 서브태스크 CASCADE 삭제 |
| `get_upcoming_deadlines` | 마감 임박 과제 조회 |

**자동 분해 흐름:**

```
사용자 입력
"자료구조 프로젝트 과제 추가해줘.
 마감일은 2026-06-10이고 단계별로 나눠줘."
        │
        ▼
   유형 감지 (_detect_assignment_type)
   제목·설명 키워드 분석
        │
   ┌────┴──────────────────────────────────┐
   │ presentation │ report │ coding        │
   │ exam         │ general               │
   └────┬──────────────────────────────────┘
        ▼
   템플릿 선택 → 5~7개 서브태스크 생성
   마감일 역산: 부모 마감일 기준 단계별 배분
        │
        ▼
   SQLite assignment_subtasks 저장
        │
        ▼
   진행률 = 완료된 서브태스크 / 전체 서브태스크
   서브태스크 완료 시 부모 과제 상태 자동 갱신
   (0% → pending, 1~99% → in_progress, 100% → done)
```

**각 유형별 템플릿 예시:**

| 유형 | 키워드 | 서브태스크 수 |
|---|---|---|
| presentation | 발표, PPT, 프레젠테이션 | 6개 |
| report | 보고서, 레포트, 조사 | 6개 |
| coding | 프로젝트, 구현, 개발, 코딩 | 6개 |
| exam | 시험, 중간고사, 기말고사 | 5개 |
| general | (기타) | 6개 |

**발표 대본 요점:**
사용자가 "단계별로 나눠줘"처럼 키워드를 넣으면 `add_task_with_subtasks`가 자동으로 호출됩니다. 제목과 설명을 분석해 과제 유형을 감지하고, 그에 맞는 단계 템플릿을 적용합니다. 서브태스크 완료를 체크하면 부모 과제 상태가 자동으로 바뀝니다.

**대시보드 UI 특징:**
- 과제별 프로그레스 바(진행률 %)
- 서브태스크 체크박스 — 체크 즉시 DB 업데이트 + 화면 갱신
- 긴급(High) 과제만 필터 토글
- 요약 지표: 전체 과제 / 완료 과제 / 서브태스크 수

### Slide 07 · 캘린더 · 일정 (CALENDAR)

**슬라이드 제목:** 자연어 일정은 실제 날짜와 D-day로 바뀐다.

**캘린더 도구 6개:**

| 도구 | 역할 |
|---|---|
| `add_calendar_event` | 일정 추가 (제목·날짜·시간·카테고리) |
| `list_calendar_events` | 일정 목록 조회 (카테고리·날짜 필터) |
| `get_today_schedule` | 오늘 일정 조회 |
| `get_week_schedule` | 기간 일정 조회 |
| `delete_calendar_event` | 일정 삭제 |
| `check_dday` | D-day 계산 |

**일정 카테고리 4종:**

| 카테고리 | 색상 | 사용 예 |
|---|---|---|
| class (수업) | 초록 | 자료구조 수업 |
| exam (시험) | 빨강 | 기말고사 |
| personal (개인) | 파랑 | 개인 약속 |
| meeting (모임) | 주황 | 팀 미팅 |

**날짜 변환 규칙 (중요):**
- Agent는 현재 시스템 시간을 컨텍스트로 주입받음
- "내일", "다음 주 수요일", "이번 주 금요일" → 에이전트가 절대 날짜(YYYY-MM-DD)로 변환 후 도구 호출
- Pydantic `field_validator`가 날짜 형식 강제 검증

**입력 예시:**
```
"내일 오전 9시에 자료구조 수업 추가해줘."
→ add_calendar_event(title="자료구조 수업", date="2026-06-06", start_time="09:00", category="class")

"기말고사 D-day 확인해줘."
→ check_dday(category="exam")
→ D-3 | 기말고사 (2026-06-08)
```

**캘린더 UI 특징:**
- 월별 그리드 렌더링 (순수 HTML/CSS, 다크모드 대응)
- 과제·일정 배지를 우선순위/카테고리 색상으로 표시
- ◀ ▶ 월 이동, 과제/일정 필터 라디오

### Slide 08 · 공지사항 RAG 검색 (RAG)

**슬라이드 제목:** 학교 공지는 저장 검색과 실시간 크롤링을 함께 사용한다.

**RAG 도구 5개:**

| 도구 | 역할 |
|---|---|
| `search_university_notices` | **학과** 공지 검색 (컴퓨터시스템공학과) |
| `search_school_notices` | **학교 대표** 공지 검색 (인하공전 전체) |
| `load_notice_data` | 로컬 JSON 파일에서 공지 로드 |
| `get_notice_stats` | 저장 공지 현황 |
| `clear_notice_data` | 공지 데이터 전체 삭제 |

**검색 파이프라인 흐름:**

```
사용자: "학과 장학금 공지 찾아줘"
        │
        ▼
ChromaDB 캐시 검색
(관련도 0.45 이상 결과 있음?)
        │
  있음──┤──없음
        │         │
        │         ▼
        │   실시간 크롤링
        │   학과 K2Web BBS 또는
        │   학교 combBbs 게시판
        │         │
        │         ▼
        │   청킹(500자) · 임베딩
        │   ChromaDB에 저장
        │         │
        └─────────┘
              │
              ▼
         결과 응답
   제목 · 날짜 · 요약 · URL
   후속: "마감일을 과제/캘린더에 등록하시겠어요?"
```

**크롤링 대상:**

| 대상 | 게시판 방식 | 검색 방법 |
|---|---|---|
| 컴퓨터시스템공학과 | K2Web BBS (`enc` 파라미터) | 키워드 직접 검색 |
| 인하공전 대표 공지 | combBbs (`jf_combBbs_view()`) | URL 패턴 변환 |

**RAG 파이프라인 구성:**
- `loader.py`: JSON/텍스트 → dict 리스트 변환
- `chunker.py`: SimpleTextChunker (500자, overlap 50자)
- `embedder.py`: ChromaDB PersistentClient (`university_notices` 컬렉션)
- `retriever.py`: 유사도 검색, 관련도 점수 반환

### Slide 11 · 장기기억 · 대화 저장 (MEMORY)

**슬라이드 제목:** 대화와 사용자 설정은 로컬에 저장된다.

**두 가지 기억 레이어:**

**① 단기 문맥 — LangGraph MemorySaver**
- 앱 실행 중 대화 흐름 유지 (`thread_id: "streamlit_session"`)
- 도구 호출 후 다시 Agent로 복귀하는 순환 흐름 유지
- 상대 날짜 해석에 현재 시간 주입

**② 장기 저장 — SQLite conversation tables**

| 테이블 | 역할 |
|---|---|
| `conversation_sessions` | 세션 기본 정보 |
| `conversation_messages` | role·content·시간 저장 |
| `memory_summaries` | 요약 메모리 (테이블·함수 준비됨) |

- 앱 재실행 후 최근 20개 대화 자동 복원
- 전공·학년·관심 영역 설정 SQLite `user_settings`에 영구 저장

**현재 구현 한계 (솔직하게 명시):**
> 자동 요약 메모리는 테이블과 함수(`save_memory_summary`, `get_latest_memory_summary`)만 준비된 상태입니다. 현재 범위에서는 대화 원문 저장·복원 중심으로 동작합니다.

**SQLite 7개 테이블 전체:**

| 테이블 | 역할 |
|---|---|
| assignments | 과제 저장 |
| assignment_subtasks | 서브태스크 저장 (FK → assignments) |
| schedules | 일정 저장 |
| user_settings | 사용자 설정 Key-Value |
| conversation_sessions | 대화 세션 |
| conversation_messages | 메시지 이력 |
| memory_summaries | 요약 메모리 |

**슬라이드 제목:** 시연은 기능보다 사용자 흐름이 보이게 구성한다.

### Slide 15 · Q&A

**Q&A 슬라이드 문구:**
- 슬라이드 중앙: **Q & A**
- 프로젝트 GitHub 또는 코드 위치 표시

**예상 질문과 답변 (발표자 준비용):**

**Q1. 외부 API 없으면 어떻게 되나요?**
> API 키가 없으면 도구가 설정 안내 메시지를 반환합니다. `search_student_info`로 사전 저장된 샘플 데이터를 검색하는 것은 API 키 없이도 작동합니다.

**Q2. 자동 요약 메모리가 미완성이라고 했는데, 대화가 길어지면 어떻게 되나요?**
> LangGraph MemorySaver가 세션 내 대화를 유지하고, SQLite에 원문을 저장합니다. 자동 요약 기능이 없기 때문에 현재는 대화가 매우 길어지면 LLM에 전달하는 컨텍스트 창이 커질 수 있습니다. 이것이 다음 개선 우선순위 1번입니다.

**Q3. ChromaDB 컬렉션이 하나라는 문제는 실제로 얼마나 영향이 있나요?**
> 현재 `category` 메타데이터로 공지사항과 대학생 정보를 구분하므로 검색에는 큰 문제가 없습니다. 다만 `clear_notice_data`를 실행하면 두 종류 데이터가 모두 삭제되는 안전 리스크가 있습니다.
