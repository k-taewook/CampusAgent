## 1. 표지

### 슬라이드 제목

CampusAgent.

### 슬라이드 핵심 문장

대학생의 과제, 일정, 공지사항, 학생 정보를 하나의 대화형 인터페이스에서 관리하는 로컬 AI 학생 비서.

### 발표 멘트 초안

안녕하세요.
저는 대학생의 과제 관리, 일정 관리, 학교 공지 검색, 학생 정보 탐색을 하나로 묶은 로컬 AI 학생 비서 CampusAgent를 개발했습니다.
이 프로젝트는 단순히 질문에 답하는 챗봇이 아니라, 사용자의 요청을 실제 과제 등록, 일정 조회, 공지 검색 같은 행동으로 연결하는 것을 목표로 했습니다.

## 2. 문제 배경

### 슬라이드 제목

대학생 정보는 너무 흩어져 있다.

### 핵심 내용

- 과제는 메모 앱이나 LMS에 따로 존재한다.
- 일정은 캘린더에 따로 입력해야 한다.
- 학과 공지와 학교 공지는 별도 홈페이지에서 확인해야 한다.
- 장학금, 청년정책, 공모전, 인턴십 정보는 외부 사이트에 흩어져 있다.
- 사용자는 정보를 찾은 뒤 다시 본인의 할 일로 옮겨야 한다.

### 발표 멘트 초안

대학생은 매주 과제, 시험, 수업 일정, 학교 공지, 장학금, 공모전 같은 정보를 계속 확인해야 합니다.
문제는 이 정보들이 한곳에 있지 않다는 점입니다.
사용자는 학교 홈페이지를 보고, 공공기관 사이트를 보고, 다시 개인 캘린더나 메모 앱에 옮겨 적어야 합니다.
저는 이 과정을 자연어 대화 하나로 줄이는 시스템을 만들고자 했습니다.

## 3. 프로젝트 목표

### 슬라이드 제목

목표: 대화에서 실제 관리까지.

### 핵심 내용

- 자연어로 과제와 일정을 관리한다.
- 학교 및 학과 공지를 실시간으로 검색한다.
- 편입학, 장학금, 청년정책, 공모전, 인턴십 정보를 사용자 조건에 맞춰 추천한다.
- 큰 과제를 서브태스크로 자동 분해한다.
- 대화 기록과 사용자 설정을 로컬에 저장한다.

### 발표 멘트 초안

CampusAgent의 핵심 목표는 대화에서 끝나는 AI가 아니라 실제 관리까지 이어지는 AI를 만드는 것입니다.
예를 들어 사용자가 "자료구조 프로젝트를 단계별로 나눠줘."라고 말하면, 시스템은 과제를 등록하고 서브태스크까지 생성합니다.
"학과 장학금 공지 찾아줘."라고 말하면 실제 학교 홈페이지를 검색하고 관련 공지를 보여줍니다.

## 4. 전체 시스템 구조

### 슬라이드 제목

LangGraph Agent + Tools + Local Storage.

### 핵심 내용

```text
사용자 입력
-> Streamlit UI
-> LangGraph Agent
-> LLM 도구 호출 판단
-> Task / Calendar / RAG / Student Info Tools
-> SQLite / ChromaDB / 외부 API / 웹 크롤러
-> 최종 응답
```

### 발표 멘트 초안

전체 구조는 Streamlit UI, LangGraph Agent, 도구 계층, 저장소 계층으로 나뉩니다.
사용자가 채팅창에 요청을 입력하면 LangGraph Agent가 이를 해석합니다.
필요하면 과제 도구, 일정 도구, 공지 검색 도구, 학생 정보 검색 도구 중 하나를 호출합니다.
구조화된 데이터는 SQLite에 저장하고, 검색이 필요한 공지와 학생 정보는 ChromaDB에 저장합니다.

## 5. 기술 스택

### 슬라이드 제목

사용 기술.

### 핵심 내용

| 영역 | 기술 |
|---|---|
| UI | Streamlit |
| Agent | LangGraph |
| LLM | Gemini 또는 OpenAI |
| Tool | LangChain `@tool` |
| 구조화 저장소 | SQLite |
| 벡터 검색 | ChromaDB |
| RAG | 크롤링, 청킹, 임베딩, 유사도 검색 |
| 외부 정보 | 온통청년, 워크넷, K-스타트업, 학교 홈페이지 |

### 발표 멘트 초안

UI는 Streamlit으로 만들었고, Agent 흐름은 LangGraph로 구성했습니다.
LLM은 Gemini와 OpenAI 중 환경변수에 설정된 키를 자동으로 감지합니다.
과제와 일정은 SQLite에 저장하고, 공지나 학생 정보처럼 검색해야 하는 텍스트는 ChromaDB에 저장했습니다.
외부 정보는 학교 홈페이지 크롤링과 공공 API를 통해 가져오도록 했습니다.

## 6. 핵심 기능 1: 과제 관리와 자동 분해

### 슬라이드 제목

큰 과제를 실행 가능한 작업으로 나누기.

### 핵심 내용

- 일반 과제 추가, 조회, 상태 변경, 삭제.
- 큰 과제 자동 분해.
- 발표형, 보고서형, 코딩형, 시험형, 일반형 템플릿.
- 5~7개 서브태스크 생성.
- 서브태스크 완료율 기반 부모 과제 진행률 계산.

### 시연 문장

```text
자료구조 프로젝트 과제 추가해줘. 마감일은 2026-06-10이고 단계별로 나눠줘.
```

### 발표 멘트 초안

CampusAgent의 과제 기능은 단순 CRUD에서 끝나지 않습니다.
큰 과제를 입력하면 제목과 설명의 키워드를 기반으로 발표형, 보고서형, 코딩형 같은 유형을 추정합니다.
그 뒤 5~7개의 서브태스크를 생성하고, 서브태스크 완료율에 따라 부모 과제 진행률을 계산합니다.
이 기능은 학생이 막연한 큰 과제를 실제 실행 가능한 단계로 바꾸는 데 초점을 두었습니다.

## 7. 핵심 기능 2: 일정 관리

### 슬라이드 제목

자연어 일정 관리.

### 핵심 내용

- 일정 추가.
- 오늘 일정 조회.
- 기간별 일정 조회.
- D-day 계산.
- 수업, 시험, 개인, 모임 등 카테고리 구분.
- 상대 날짜를 현재 날짜 기준 절대 날짜로 변환.

### 시연 문장

```text
내일 오전 9시에 자료구조 수업 추가해줘.
이번 주 일정 보여줘.
```

### 발표 멘트 초안

일정 관리는 사용자가 자연어로 말한 날짜를 실제 날짜로 변환해 저장하는 방식입니다.
예를 들어 "내일", "이번 주" 같은 표현은 현재 시스템 시간을 기준으로 계산됩니다.
일정은 수업, 시험, 개인, 모임 등으로 나누어 저장하고, 캘린더 탭에서 월별로 확인할 수 있습니다.

## 8. 핵심 기능 3: 학교 공지 RAG 검색

### 슬라이드 제목

학교 공지를 직접 찾아주는 RAG 검색.

### 핵심 내용

- 학과 공지와 학교 대표 공지 구분.
- 저장된 ChromaDB 결과 우선 검색.
- 결과 부족 시 학교 홈페이지 실시간 크롤링.
- 공지 제목, 날짜, 카테고리, 요약, URL 표시.
- 검색 결과를 이후 재검색할 수 있도록 저장.

### 시연 문장

```text
학과 장학금 공지 찾아줘.
학교 등록금 공지 검색해줘.
```

### 발표 멘트 초안

공지 검색 기능은 RAG 구조를 사용합니다.
먼저 ChromaDB에 저장된 공지 중 관련 결과를 찾고, 부족하면 실제 학교 홈페이지를 크롤링합니다.
수집한 공지는 다시 청킹과 임베딩을 거쳐 저장되므로 다음 검색에서 더 빠르게 활용할 수 있습니다.

## 9. 핵심 기능 4: 대학생 정보 추천

### 슬라이드 제목

내 정보에 맞는 대학생 정보 추천.

### 핵심 내용

- 편입학과 전공심화 정보.
- 국가장학금과 청년정책.
- 공모전과 대외활동.
- 현장실습과 인턴십.
- 전공, 학년, 관심 영역, 희망 진로를 반영한 개인화 검색.
- 청년정책은 지역, 나이, 재학 상태, 취업 상태가 있으면 후보 우선순위에 반영.
- 온통청년, 워크넷, K-스타트업, 학교 공지 검색 연동.

### 발표 멘트 초안

대학생에게 필요한 정보는 학교 안에만 있지 않습니다.
장학금, 청년정책, 공모전, 인턴십 정보는 외부 공공기관이나 포털에 흩어져 있습니다.
CampusAgent는 전공, 학년, 관심 영역, 희망 진로 같은 사용자 정보를 바탕으로 이런 정보를 추천합니다.
편입학은 학교 입학처 공식 경로를 우선 안내하고, 청년정책은 사용자가 말한 지역, 나이, 재학 상태, 취업 상태를 반영해 확인해볼 만한 후보를 우선 보여줍니다.
다만 정책의 실제 신청 가능 여부는 소득, 거주, 신청 기간 같은 세부 조건에 따라 달라지므로, 최종 판단은 원문에서 확인하도록 안내합니다.

## 10. 핵심 기능 5: 장기기억과 설정

### 슬라이드 제목

대화와 설정을 로컬에 저장.

### 핵심 내용

- `MemorySaver`로 실행 중 대화 문맥 유지.
- SQLite에 대화 세션과 메시지 저장.
- 앱 재실행 후 최근 대화 복원.
- 전공, 학년, 관심 영역, 희망 진로를 프롬프트와 학생 정보 추천에 반영.
- 자동 요약 메모리는 향후 개선 항목.

### 발표 멘트 초안

CampusAgent는 대화 내용을 단순히 화면에만 보여주지 않고 SQLite에 저장합니다.
앱을 다시 실행해도 최근 대화를 복원할 수 있고, 사용자의 전공이나 학년 같은 설정을 Agent 프롬프트에 반영합니다.
다만 자동으로 오래된 대화를 요약하는 기능은 테이블과 함수만 준비된 상태이며, 최종 범위에서는 대화 저장과 복원 중심으로 구현했습니다.

## 12. 한계와 개선 방향

### 슬라이드 제목

완성한 것과 남겨둔 것.

### 핵심 내용

완성한 것.

- 과제·일정·공지·학생 정보 통합 Agent.
- 과제 자동 분해와 진행률 계산.
- SQLite 기반 대화 저장.
- 학교 공지 RAG 검색.
- 개인화 대학생 정보 추천.
- 외부 공공 정보 검색 도구와 조건 기반 후보 안내.

한계.

- 청년 정책의 실제 신청 가능 여부는 소득, 거주, 신청 기간 등 세부 조건까지 자동 확정하기 어렵다.
- 외부 API와 웹 크롤링은 원격 사이트 상태에 의존한다.
- 공지와 학생 정보 ChromaDB 컬렉션 분리가 필요하다.
- 자동 요약 메모리는 향후 과제다.
- Multi-Agent 구조는 구현 범위에서 제외하고 향후 개선으로 남겼다.

### 발표 멘트 초안

이번 프로젝트에서 핵심 기능은 시연 가능한 수준으로 구현했습니다.
하지만 모든 기능을 완전 자동화했다고 말할 수는 없습니다.
특히 청년 정책 추천은 개인 조건과 정책 세부 조건이 필요하기 때문에, 관련성이 높은 후보를 추천하고 원문 확인을 돕는 기능으로 보는 것이 맞습니다.
향후에는 사용자 프로필을 확장하고, 공공 정책 조건을 구조화하며, 공지와 학생 정보 저장소를 분리하고, Multi-Agent 구조를 도입하는 방향으로 개선할 수 있습니다.

## 13. 결론

### 슬라이드 제목

CampusAgent의 의미.

### 핵심 내용

- 단순 챗봇이 아니라 실제 작업을 수행하는 학생 비서.
- 로컬 저장소와 RAG 검색을 결합한 학업 관리 시스템.
- 자연어 요청을 과제, 일정, 공지, 정보 검색 행동으로 연결.
- 향후 정책 자격 조건 구조화와 Multi-Agent 구조로 확장 가능.

### 발표 멘트 초안

CampusAgent는 대학생이 매일 관리해야 하는 정보를 하나의 대화형 흐름으로 묶는 프로젝트입니다.
LLM은 사용자의 의도를 해석하고, 실제 데이터 처리는 도구와 저장소가 담당합니다.
이 구조를 통해 챗봇이 단순한 답변기를 넘어 과제와 일정, 공지 검색, 대학생 정보 추천을 수행하는 학생 비서로 동작할 수 있음을 확인했습니다.

---

## 14. 시연 순서

### 시연 1. 큰 과제 자동 분해

입력.

```text
자료구조 프로젝트 과제 추가해줘. 마감일은 2026-06-10이고 단계별로 나눠줘.
```

확인할 점.

- 부모 과제 생성.
- 5~7개 서브태스크 생성.
- 과제 대시보드에 진행률 표시.

### 시연 2. 서브태스크 완료와 진행률 반영

확인할 점.

- 과제 대시보드에서 서브태스크 일부 체크.
- 부모 과제 진행률 증가.
- 전체 완료 시 부모 과제 상태 변경.

### 시연 3. 공지 검색

입력.

```text
학과 장학금 공지 찾아줘.
```

확인할 점.

- 학과 공지 검색 도구 호출.
- 공지 제목, 날짜, 요약, URL 표시.

### 시연 4. 일정 조회

입력.

```text
이번 주 일정 보여줘.
```

확인할 점.

- 기간별 일정 조회.
- 캘린더 탭과 연결 설명.

### 시연 5. 학생 정보 추천

입력.

```text
나는 인천에 사는 24세 대학생이고 아직 취업 안 했어. 내가 받을 수 있는 청년 정책 찾아줘.
```

확인할 점.

- 사용자 조건을 반영한 청년정책/장학금 후보 표시.
- 결과를 확정 판정이 아니라 조건 확인용 후보로 안내.
- 실제 신청 가능 여부는 원문 확인이 필요하다고 설명.

## 15. 예상 질문과 답변

### Q1. 왜 LangGraph를 사용했나요?

LangGraph는 LLM 호출과 도구 실행 흐름을 그래프로 제어할 수 있어, 단순 챗봇보다 도구 기반 작업 수행 구조를 만들기 좋기 때문입니다.
CampusAgent에서는 Agent가 응답만 생성하는 것이 아니라 과제, 일정, 검색 도구를 호출해야 하므로 LangGraph 구조가 적합했습니다.

### Q2. 공지 검색은 그냥 키워드 검색과 무엇이 다른가요?

단순 키워드 검색은 제목이나 본문에 같은 단어가 있어야 잘 찾습니다.
CampusAgent는 공지를 청킹하고 ChromaDB에 저장해 의미 기반 검색을 수행합니다.
또한 저장된 데이터가 부족하면 학교 홈페이지를 실시간으로 크롤링해 최신 정보를 보강합니다.

### Q3. 청년 정책 추천이 정확한가요?

사용자의 조건과 관련성이 높은 정책 후보를 찾는 데는 도움이 되지만, 실제 신청 가능 여부를 확정하지는 않습니다.
정확한 판정에는 나이, 거주 지역, 소득, 취업 상태, 재학 상태 같은 조건이 필요합니다.
그래서 최종 시스템에서는 추천할 만한 정책 후보를 우선 보여주고 원문 확인을 안내하는 방식으로 구현했습니다.

### Q4. 장기기억은 어디까지 구현됐나요?

대화 세션, 메시지 저장, 최근 대화 복원은 SQLite로 구현했습니다.
자동 요약 생성은 테이블과 함수는 준비했지만 최종 구현 범위에는 포함하지 않았습니다.
따라서 발표에서는 저장과 복원 중심의 장기기억으로 설명하는 것이 정확합니다.

### Q5. Multi-Agent 구조는 구현됐나요?

아니요.
초기에는 12주차에 Supervisor와 specialist 구조를 구현하려 했지만, 일정 변경으로 12주차부터는 기존 기능 보완과 최종 발표, 최종보고서 준비로 전환했습니다.
Multi-Agent 구조는 향후 개선 방향으로 남겼습니다.

## 16. 발표 마무리 멘트

CampusAgent는 대학생이 매일 반복하는 정보 확인과 일정 관리를 하나의 대화형 흐름으로 줄이기 위한 프로젝트입니다.
이번 구현에서는 과제, 일정, 공지, 학생 정보 검색을 하나의 Agent에 연결했고, 큰 과제를 서브태스크로 나누는 기능까지 추가했습니다.
앞으로 정책 자격 조건 구조화와 Multi-Agent 구조를 보완하면 더 개인화된 학생 비서로 발전시킬 수 있습니다.
