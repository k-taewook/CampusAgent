# CampusAgent UI/UX 개선 제안

작성일: 2026-05-19.  
기준 파일: `app.py`.  
목적: 현재 Streamlit UI를 더 깔끔하고 사용하기 편한 학습 관리 도구로 개선하기 위한 제안 정리.

## 1. 현재 UI/UX 평가

현재 CampusAgent UI는 4개 탭 구조로 기능을 명확히 나누고 있다.

| 영역 | 현재 역할 | 평가 |
|---|---|---|
| 사이드바 | LLM 상태, 긴급 알림, 공지 RAG 현황, 사용 예시 표시 | 정보가 많아 첫 화면에서 다소 복잡하게 느껴질 수 있음. |
| 챗봇 탭 | 자연어 대화, 추천 명령어, RAG 후속 액션 | 핵심 진입점으로 적절하지만 추천 명령어가 고정되어 있어 상황 반영이 약함. |
| 과제 대시보드 | 과제 목록, 긴급 과제 필터, 완료 체크 | 실용적이지만 표 중심이라 우선순위와 진행 상태가 한눈에 강하게 들어오지는 않음. |
| 캘린더 탭 | 월별 일정·과제 표시 | 직접 구현한 달력이라 기능은 있으나 일정이 많아지면 밀도가 높아질 수 있음. |
| 설정 탭 | 전공, 학년, 알림 기준일, LLM 표시 | 필요한 설정은 있으나 사용 빈도가 낮은 정보가 메인 탭과 같은 무게로 있음. |

전체적으로 기능은 잘 분리되어 있지만, 사용자가 앱을 열었을 때 “지금 무엇을 해야 하는지”가 가장 먼저 보이기보다는 기능 탭을 탐색해야 하는 구조다.

## 2. 개선 방향 요약

가장 추천하는 방향은 **오늘 할 일 중심의 작업형 대시보드**로 바꾸는 것이다.

현재 구조는 다음에 가깝다.

```text
챗봇 / 과제 / 캘린더 / 설정
```

개선 후에는 다음 흐름이 더 자연스럽다.

```text
오늘 / 채팅 / 과제 / 캘린더 / 검색 / 설정
```

핵심은 챗봇만 앞세우기보다, 사용자가 앱을 열자마자 오늘의 마감, 일정, 추천 행동을 보고 바로 처리할 수 있게 만드는 것이다.

## 3. 추천 정보 구조

### 3.1 첫 화면을 `오늘` 탭으로 변경

현재 첫 탭은 챗봇이다. 하지만 학생 입장에서는 매번 가장 궁금한 것이 다음과 같다.

- 오늘 마감인 과제가 있는가?
- 오늘 수업이나 시험이 있는가?
- 이번 주 안에 끝내야 할 일이 무엇인가?
- 새로 확인할 공지가 있는가?

따라서 첫 탭을 `오늘`로 두고, 챗봇은 두 번째 탭으로 두는 구성이 더 사용하기 쉽다.

추천 탭 구조:

```text
오늘 | 채팅 | 과제 | 캘린더 | 검색 | 설정
```

`오늘` 탭 구성:

| 영역 | 내용 |
|---|---|
| 상단 요약 | 오늘 일정 수, 오늘 마감 과제 수, 이번 주 마감 과제 수, 저장 공지 수. |
| 오늘 일정 | 시간순 일정 리스트. |
| 마감 임박 과제 | D-day 기준 정렬된 과제 리스트. |
| 추천 행동 | “오늘 일정 확인”, “마감 과제 보기”, “장학금 공지 검색” 같은 상황 기반 버튼. |
| 최근 대화 이어가기 | 마지막 대화 1~2개만 요약 표시. |

이렇게 하면 사용자는 챗봇에게 묻기 전에도 앱의 가치를 바로 느낄 수 있다.

### 3.2 사이드바는 시스템 상태 중심으로 축소

현재 사이드바는 긴급 알림, RAG 현황, 사용 예시까지 포함한다. 이 정보들은 유용하지만 사이드바에 모두 있으면 시선이 분산된다.

추천 변경:

- 사이드바에는 앱 이름, LLM 연결 상태, 전공·학년, 저장된 문서 수만 남긴다.
- 긴급 알림은 `오늘` 탭의 메인 콘텐츠로 이동한다.
- 사용 예시는 챗봇 탭의 빈 상태나 추천 버튼 영역으로 이동한다.

사이드바 추천 구성:

```text
CampusAgent
v0.9.0

LLM: Gemini 연결됨
전공: 컴퓨터시스템공학과
학년: 2학년

공지 문서: 000건
대화 세션: streamlit_session
```

## 4. 챗봇 UX 개선

### 4.1 추천 명령어를 상황 기반으로 변경

현재 추천 명령어는 고정 버튼이다.

```text
오늘 일정 보여줘
마감 임박 과제
장학금 공지 검색
저장 공지 삭제
```

고정 버튼보다 상황 기반 버튼이 더 유용하다.

추천 예시:

| 상황 | 버튼 |
|---|---|
| 오늘 일정 있음 | `오늘 일정 요약해줘` |
| 3일 내 마감 과제 있음 | `마감 과제 우선순위 정리해줘` |
| 저장 공지 없음 | `공지 데이터 불러오기` |
| 전공 미설정 | `전공 설정하러 가기` |
| 최근 공지 검색 후 | `이 공지를 과제로 등록하기` |

### 4.2 위험한 버튼은 일반 추천 버튼에서 분리

현재 `저장 공지 삭제`가 추천 명령어 버튼에 포함되어 있다. 이 기능은 ChromaDB 데이터를 삭제할 수 있으므로 일반 추천 버튼과 같은 위치에 두기에는 위험하다.

추천 변경:

- `저장 공지 삭제`는 설정 탭 또는 검색 탭의 “데이터 관리” 섹션으로 이동한다.
- 삭제 전 확인 절차를 둔다.
- 버튼 문구는 `공지 데이터 초기화`처럼 영향 범위를 분명히 한다.

### 4.3 채팅 응답 영역과 입력 영역의 시각적 분리

현재 채팅 컨테이너 높이는 고정되어 있고, 추천 버튼은 입력창 위에 있다. 추천 버튼이 계속 보이면 대화 흐름이 다소 끊겨 보일 수 있다.

추천 변경:

- 추천 버튼은 대화가 비어 있을 때 더 크게 보여준다.
- 대화가 시작된 뒤에는 작은 `빠른 실행` 메뉴로 접는다.
- RAG 후속 액션은 응답 바로 아래에 유지한다.

## 5. 과제 대시보드 개선

### 5.1 표 중심에서 카드 + 리스트 혼합으로 변경

현재 과제 대시보드는 `st.data_editor` 중심이다. 표는 많은 정보를 한 번에 보기 좋지만, 학생이 실제로 해야 할 일의 우선순위를 파악하기에는 다소 건조하다.

추천 구성:

```text
상단 메트릭
- 전체 과제
- 오늘 마감
- 이번 주 마감
- 완료율

필터
- 전체 / 진행 중 / 완료
- 전체 / 높음 / 보통 / 낮음

과제 리스트
- D-day 배지
- 제목
- 과목
- 우선순위
- 상태 체크
- 상세 펼치기
```

### 5.2 우선순위 색상 체계를 단순화

현재 캘린더와 과제에서 색상이 여러 개 쓰인다. 색상 의미를 줄이면 더 깔끔하다.

추천 색상:

| 의미 | 색상 |
|---|---|
| 위험 / 오늘 마감 / 시험 | 빨강 |
| 주의 / 이번 주 마감 | 주황 |
| 정상 / 완료 | 초록 |
| 정보 / 수업·일반 일정 | 파랑 |
| 보조 / 완료된 과제 | 회색 |

색상은 강조용으로만 쓰고, 모든 카드가 강한 색으로 칠해지지 않게 한다.

### 5.3 11주차 서브태스크 기능을 고려한 레이아웃

서브태스크 트리가 추가되면 표 하나로는 표현이 어려워진다. 미리 다음 구조를 추천한다.

```text
과제 카드
  제목 / 과목 / 마감일 / 우선순위
  진행률 bar
  서브태스크 체크리스트
  상세 버튼
```

Streamlit에서는 `st.expander`와 `st.progress`를 활용하면 구현 난이도가 낮다.

예상 UI:

```text
[D-3] 자료구조 프로젝트                         진행률 33%
자료구조 | high | 2026-05-22
[======              ]

▾ 서브태스크
  [x] 요구사항 분석
  [x] 자료구조 설계
  [ ] 핵심 기능 구현
  [ ] 테스트 작성
  [ ] 제출 파일 정리
```

## 6. 캘린더 UX 개선

### 6.1 월간 캘린더는 유지하되 주간 보기 추가

월간 캘린더는 전체 흐름을 보기 좋지만, 실제 학생이 자주 보는 것은 이번 주 일정이다.

추천 추가:

- `월간` / `주간` segmented control.
- 기본값은 `주간`.
- 주간 보기에는 오늘부터 7일간의 일정과 과제를 날짜별 리스트로 표시.

주간 보기 예시:

```text
오늘 5/19
- 09:00 자료구조 수업
- D-day 데이터베이스 과제

내일 5/20
- 14:00 팀플 회의
```

### 6.2 캘린더 배지는 짧고 일관되게

현재 캘린더 배지는 제목을 8자 기준으로 자른다. 일정이 많아지면 의미가 잘릴 수 있다.

추천 방식:

- 배지에는 아이콘, 시간, 짧은 제목만 표시한다.
- 셀 안에서는 최대 2~3개만 보여주고, 초과분은 `+3개`로 표시한다.
- 날짜 클릭 또는 expander로 상세 목록을 보여준다.

## 7. 검색/RAG UX 개선

공지 검색과 대학생 정보 검색은 현재 챗봇 안에 섞여 있다. 기능이 커졌기 때문에 별도 `검색` 탭을 추가하면 더 명확하다.

추천 `검색` 탭 구성:

| 섹션 | 내용 |
|---|---|
| 통합 검색 입력 | 공지, 장학금, 편입, 공모전 검색. |
| 검색 범위 선택 | 학과 공지 / 학교 공지 / 대학생 정보 / 외부 정보. |
| 최근 검색 결과 | 제목, 날짜, 출처, 관련도, URL. |
| 후속 액션 | 과제로 등록, 캘린더 등록, 저장. |
| 데이터 관리 | 샘플 데이터 로드, 저장 현황 확인, 데이터 초기화. |

이렇게 하면 챗봇은 자연어 대화 중심으로 남고, 검색 탭은 정보 탐색 중심으로 역할이 분리된다.

## 8. 설정 UX 개선

설정 탭은 현재 필요한 항목만 있지만, 사용자 입장에서는 “설정 저장 후 무엇이 달라지는지”가 약하다.

추천 변경:

- 전공과 학년이 검색 개인화에 사용된다는 짧은 설명을 caption으로 유지한다.
- 저장 후 “다음 대화부터 공지 검색과 정보 검색에 반영됩니다.”라고 안내한다.
- 위험한 데이터 초기화 기능은 설정 탭의 하단 `데이터 관리` 섹션으로 이동한다.
- API 키 상태는 raw 값을 보여주지 말고 연결 여부만 표시한다.

설정 탭 추천 섹션:

```text
개인화
- 전공
- 학년
- 마감 알림 기준일

모델 상태
- Gemini 연결 여부
- OpenAI 연결 여부
- 현재 provider

데이터 관리
- 공지 저장 문서 수
- 대학생 정보 저장 상태
- 공지 데이터 초기화
```

## 9. 시각 디자인 방향

Streamlit 기본 UI를 유지하되, 과한 장식보다 작업 도구처럼 정리하는 것이 좋다.

추천 방향:

- 카드 radius는 작게 유지한다.
- 강한 색 배경은 긴급 상태에만 사용한다.
- 본문 배경은 기본 Streamlit 테마를 따른다.
- 제목 크기를 과하게 키우지 않는다.
- 탭마다 동일한 상단 구조를 사용한다.
- 이모지는 기능 구분용으로만 제한적으로 사용한다.

현재 이모지가 전반적으로 많다. 친근한 느낌은 있지만 화면이 복잡해 보일 수 있으므로 다음처럼 줄이는 것이 좋다.

| 위치 | 권장 |
|---|---|
| 탭 라벨 | 이모지 유지 가능. |
| 버튼 | 핵심 버튼만 이모지 사용. |
| 긴 리스트 항목 | 이모지 최소화. |
| 오류·성공 메시지 | Streamlit 상태 컴포넌트에 맡기기. |

## 10. 우선순위별 실행 계획

### 1단계: 레이아웃 정리

- 첫 탭을 `오늘`로 추가한다.
- 사이드바의 긴급 알림과 사용 예시를 메인 탭으로 이동한다.
- `저장 공지 삭제` 버튼을 추천 명령어에서 제거한다.

### 2단계: 과제 대시보드 개선

- 상단 메트릭 4개를 추가한다.
- 과제 리스트를 D-day와 우선순위 중심으로 재구성한다.
- 11주차 서브태스크 기능을 고려해 expander 기반 카드 구조를 도입한다.

### 3단계: 캘린더 개선

- 주간 보기 모드를 추가한다.
- 월간 캘린더 셀의 표시 개수를 제한하고 상세 보기를 제공한다.

### 4단계: 검색 탭 분리

- 공지 검색과 대학생 정보 검색을 `검색` 탭으로 분리한다.
- 검색 범위 선택과 후속 액션 버튼을 명확히 배치한다.
- 데이터 초기화는 확인 절차를 포함한다.

### 5단계: 코드 구조 분리

UI가 커지면 `app.py`를 다음처럼 나눈다.

```text
ui/
├─ sidebar.py
├─ today.py
├─ chat.py
├─ task_dashboard.py
├─ calendar_view.py
├─ search_view.py
└─ settings_view.py
```

초기에는 파일 분리보다 화면 개선이 우선이다. 다만 서브태스크, 검색 탭, 평가 탭이 추가되면 분리하는 편이 유지보수에 좋다.

## 11. 추천 최종 화면 구조

최종적으로는 다음 구조를 추천한다.

```text
사이드바
- 앱 상태
- LLM 연결 상태
- 사용자 전공/학년
- 저장 문서 수

탭
1. 오늘
   - 오늘 요약
   - 오늘 일정
   - 마감 임박 과제
   - 추천 행동

2. 채팅
   - 대화
   - 상황 기반 빠른 실행
   - 후속 액션

3. 과제
   - 메트릭
   - 필터
   - 과제 카드 / 서브태스크 트리

4. 캘린더
   - 주간 보기
   - 월간 보기
   - 날짜별 상세

5. 검색
   - 공지 검색
   - 대학생 정보 검색
   - 외부 정보 검색
   - 데이터 관리

6. 설정
   - 개인화
   - 모델 상태
   - 알림 기준
```

이 구조는 “대화형 AI”와 “실제 학습 관리 도구”의 균형이 좋다. 챗봇은 계속 핵심 기능으로 남지만, 사용자는 매번 질문을 입력하지 않아도 오늘 해야 할 일을 바로 확인하고 처리할 수 있다.

## 12. 결론

현재 UI는 기능별 탭이 명확하고 Streamlit으로 빠르게 구현하기 좋은 구조다. 다만 기능이 늘어나면서 사이드바와 챗봇 탭에 정보가 몰리고, 사용자가 앱을 열었을 때 바로 해야 할 일이 보이는 힘은 약하다.

가장 효과적인 개선은 `오늘` 탭을 중심으로 재구성하는 것이다. 그 다음 과제 대시보드를 카드형으로 바꾸고, 검색 기능을 별도 탭으로 분리하면 화면이 더 깔끔해지고 실제 사용 흐름도 좋아진다.

우선 적용할 변경은 세 가지다.

1. 첫 화면에 오늘 요약과 마감 임박 항목을 보여준다.
2. 위험한 데이터 삭제 버튼을 추천 명령어에서 분리한다.
3. 과제 대시보드를 D-day, 진행률, 서브태스크 중심으로 재구성한다.
