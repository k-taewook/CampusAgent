# CampusAgent 최종보고서 초안

작성일: 2026-05-27  
작성자: 김태욱  
프로젝트명: CampusAgent  
주제: 대학생을 위한 LangGraph 기반 로컬 AI 학생 비서.

---

## 초록

본 프로젝트는 대학생의 과제 관리, 일정 관리, 학교 공지 검색, 학생 정보 탐색을 하나의 대화형 인터페이스에서 처리하기 위한 로컬 AI 학생 비서 `CampusAgent`를 설계하고 구현한 결과를 다룬다.
기존의 일정 관리 앱이나 공지 검색 방식은 사용자가 여러 사이트와 도구를 직접 오가야 한다는 한계가 있다.
CampusAgent는 Streamlit 기반 채팅 UI, LangGraph 기반 에이전트, SQLite 저장소, ChromaDB 기반 RAG 검색, 공공 API와 웹 크롤링 도구를 결합하여 자연어 요청을 실제 작업으로 연결한다.

사용자는 "이번 주 마감 과제 알려줘.", "학과 장학금 공지 찾아줘.", "자료구조 프로젝트를 단계별로 나눠줘."처럼 자연어로 요청할 수 있다.
시스템은 요청 의도를 해석한 뒤 과제 도구, 일정 도구, 공지 검색 도구, 학생 정보 검색 도구 중 적절한 도구를 호출한다.
또한 과제 자동 분해 기능을 통해 큰 과제를 5~7개의 서브태스크로 나누고, 서브태스크 완료율에 따라 상위 과제 진행률을 계산한다.

구현 결과 CampusAgent는 과제, 일정, 공지사항, 학생 정보, 대화 기록을 통합 관리하는 로컬 학생 지원 시스템으로 동작한다.
다만 공공 API 기반 청년 정책 검색은 사용자의 나이, 거주 지역, 소득, 취업 상태 등 세부 조건이 없으면 실제 신청 가능 여부를 확정할 수 없으므로, 본 프로젝트에서는 정책 후보 탐색과 원문 확인 보조 기능으로 한정한다.

## 1. 서론

### 1.1 연구 배경

대학생은 학기 중 과제, 시험, 수업 일정, 학교 공지, 장학금, 공모전, 인턴십 등 다양한 정보를 동시에 관리해야 한다.
이 정보들은 학교 홈페이지, 학과 홈페이지, 공공기관 웹사이트, 개인 메모 앱, 캘린더 앱 등에 흩어져 있다.
사용자는 필요한 정보를 찾기 위해 여러 사이트를 직접 방문해야 하며, 찾은 정보를 다시 일정이나 과제로 등록해야 한다.

최근 LLM 기반 챗봇은 자연어 질의응답에 강점을 보이지만, 단순 대화만으로는 실제 할 일을 저장하거나 학교 공지를 검색하거나 과제 진행률을 관리하기 어렵다.
따라서 대학생에게 실질적으로 도움이 되는 AI 비서를 만들기 위해서는 LLM, 로컬 데이터베이스, 검색 시스템, 외부 정보 수집 도구가 함께 연결되어야 한다.

### 1.2 문제 정의

본 프로젝트가 해결하고자 한 문제는 다음과 같다.

1. 사용자가 과제와 일정을 여러 도구에 따로 기록해야 한다.
2. 학교 및 학과 공지를 매번 직접 찾아야 한다.
3. 장학금, 편입학, 공모전, 인턴십 같은 대학생 정보가 여러 사이트에 흩어져 있다.
4. 일반 챗봇은 사용자의 실제 과제·일정 데이터와 연결되지 않아 행동으로 이어지기 어렵다.
5. 큰 과제는 등록만으로 끝나지 않고 세부 계획과 진행률 관리가 필요하다.

### 1.3 연구 목표

CampusAgent의 목표는 다음과 같다.

- 자연어 대화로 과제와 일정을 등록, 조회, 수정, 삭제할 수 있게 한다.
- 학교 및 학과 공지를 실시간 크롤링하고 RAG 방식으로 검색한다.
- 편입학, 장학금, 청년정책, 공모전, 인턴십 정보를 통합 검색한다.
- 대화 기록과 사용자 설정을 로컬 SQLite에 저장하여 앱 재실행 후에도 기본 맥락을 유지한다.
- 큰 과제를 자동으로 서브태스크로 분해하고 진행률을 계산한다.
- Streamlit UI에서 채팅, 과제 대시보드, 캘린더, 설정을 한 화면 흐름으로 제공한다.

## 2. 관련 기술

### 2.1 LangGraph

LangGraph는 LLM 호출, 도구 실행, 상태 저장을 그래프 형태로 구성할 수 있는 프레임워크다.
CampusAgent는 `agent` 노드에서 LLM을 호출하고, 도구 호출이 필요한 경우 `tools` 노드로 이동한 뒤 다시 `agent` 노드로 돌아오는 순환 구조를 사용한다.
이 구조를 통해 LLM은 사용자의 요청을 분석하고 필요한 도구를 선택해 실제 작업을 수행할 수 있다.

### 2.2 Tool Calling

CampusAgent의 과제, 일정, 공지 검색, 학생 정보 검색 기능은 LangChain `@tool` 함수로 구현되었다.
LLM은 자연어 요청을 직접 처리하는 대신, 필요한 경우 도구를 호출해 SQLite, ChromaDB, 외부 API, 웹 크롤러와 연결된다.
이 방식은 단순 답변형 챗봇보다 실제 작업 수행 능력이 높다.

### 2.3 RAG

RAG는 외부 문서를 검색한 뒤 검색 결과를 LLM 응답에 활용하는 방식이다.
CampusAgent는 학교 공지와 학생 정보 데이터를 텍스트 청크로 나누고 ChromaDB에 저장한 뒤, 질의와 유사한 문서를 검색한다.
공지 검색에서는 기존 저장 데이터가 부족할 경우 학교 홈페이지를 실시간 크롤링하여 최신 정보를 보강한다.

### 2.4 SQLite와 ChromaDB

CampusAgent는 구조화 데이터와 비정형 검색 데이터를 분리해 저장한다.
과제, 일정, 사용자 설정, 대화 메시지는 SQLite에 저장한다.
공지사항과 학생 정보처럼 검색이 필요한 텍스트 데이터는 ChromaDB에 저장한다.
이 구조는 트랜잭션이 필요한 데이터와 의미 기반 검색이 필요한 데이터를 각 목적에 맞게 다룰 수 있다는 장점이 있다.

## 3. 시스템 설계

### 3.1 전체 구조

CampusAgent는 다음 계층으로 구성된다.

| 계층 | 주요 파일 | 역할 |
|---|---|---|
| UI | `app.py` | Streamlit 채팅, 과제 대시보드, 캘린더, 설정 화면 제공. |
| Agent | `agent/graph.py`, `agent/prompts.py` | LangGraph 에이전트 구성, 도구 호출 판단, 시스템 프롬프트 관리. |
| Tools | `mcp_servers/` | 과제, 일정, 공지, 학생 정보 기능을 도구로 제공. |
| Database | `database/db.py`, `database/models.py` | SQLite 테이블 생성, CRUD, Pydantic 검증. |
| RAG | `rag/` | 공지 크롤링, 청킹, 임베딩, 검색, 외부 API 연동. |
| Tests | `tests/` | 과제, 일정, 메모리, RAG, 학생 정보, Agent 구성 테스트. |

전체 실행 흐름은 다음과 같다.

```text
사용자 입력
-> Streamlit 채팅 UI
-> LangGraph Agent
-> LLM이 도구 호출 여부 판단
-> ToolNode에서 과제/일정/RAG/학생정보 도구 실행
-> SQLite, ChromaDB, 외부 API, 크롤러 접근
-> 도구 결과를 바탕으로 최종 응답 생성
```

### 3.2 Agent 구조

`agent/graph.py`는 Gemini 또는 OpenAI API 키를 자동 감지하여 사용 가능한 LLM을 생성한다.
API 키가 없으면 사용자에게 설정 방법을 안내하는 fallback 메시지를 반환한다.

현재 Agent에 바인딩되는 도구는 다음 네 묶음이다.

- `TASK_TOOLS`: 과제 관리 및 서브태스크 관리.
- `CALENDAR_TOOLS`: 일정 추가, 조회, 삭제, D-day 계산.
- `RAG_TOOLS`: 학과 공지, 학교 대표 공지, 공지 데이터 관리.
- `STUDENT_INFO_TOOLS`: 편입학, 장학금, 청년정책, 인턴십, 공모전 정보 검색.

### 3.3 저장소 설계

SQLite에는 다음 데이터가 저장된다.

| 테이블 | 역할 |
|---|---|
| `assignments` | 과제 기본 정보 저장. |
| `assignment_subtasks` | 부모 과제에 연결된 서브태스크 저장. |
| `schedules` | 일정 정보 저장. |
| `user_settings` | 전공, 학년, 알림 기준일 등 사용자 설정 저장. |
| `conversation_sessions` | 대화 세션 정보 저장. |
| `conversation_messages` | 대화 메시지 원문 저장. |
| `memory_summaries` | 장기기억 요약 저장을 위한 테이블. |

ChromaDB에는 공지사항과 학생 정보 검색용 텍스트가 저장된다.
현재 구현은 하나의 검색 컬렉션을 중심으로 metadata를 통해 카테고리와 출처를 구분한다.
향후에는 공지사항과 학생 정보 컬렉션을 분리하는 것이 바람직하다.

### 3.4 UI 설계

Streamlit UI는 네 개의 탭으로 구성된다.

| 탭 | 역할 |
|---|---|
| 챗봇 | 자연어 입력, 도구 호출 결과 확인, 빠른 명령 실행. |
| 과제 대시보드 | 과제 목록, 진행률, 서브태스크 체크 UI 제공. |
| 캘린더 | 월별 일정과 과제 마감일 확인. |
| 설정 | 전공, 학년, 알림 기준일, LLM 설정 확인. |

이 구조는 대화형 인터페이스와 직접 조작형 대시보드를 함께 제공하기 위한 것이다.

## 4. 구현 내용

### 4.1 과제 관리

과제 관리 기능은 과제 추가, 조회, 상태 변경, 삭제, 마감 임박 조회를 제공한다.
사용자는 "자료구조 과제 추가해줘. 마감일은 6월 10일."처럼 말하면 Agent가 날짜를 `YYYY-MM-DD` 형식으로 변환하고 `add_task` 도구를 호출한다.

11주차에는 과제 자동 분해 기능을 추가했다.
사용자가 "큰 과제", "프로젝트", "발표", "레포트", "단계별로 나눠줘" 같은 표현을 사용하면 `add_task_with_subtasks` 도구를 호출한다.
시스템은 과제 유형을 규칙 기반으로 판별하고 5~7개의 서브태스크를 생성한다.

지원하는 과제 유형은 다음과 같다.

| 유형 | 감지 키워드 | 예시 서브태스크 |
|---|---|---|
| 발표형 | 발표, PPT, 프레젠테이션 | 요구사항 확인, 자료 조사, 슬라이드 구성, 대본 작성, 리허설. |
| 보고서형 | 보고서, 레포트, 조사 | 주제 확인, 자료 조사, 목차 작성, 초안 작성, 검토 및 제출. |
| 코딩형 | 프로젝트, 구현, 개발, 코딩 | 요구사항 분석, 구조 설계, 핵심 기능 구현, 테스트 작성, 제출 정리. |
| 시험형 | 시험, 중간고사, 기말고사 | 범위 확인, 핵심 개념 요약, 문제 풀이, 오답 정리, 최종 복습. |
| 일반형 | 기타 | 요구사항 정리, 자료 수집, 작업 계획, 본 작업, 검토, 제출. |

서브태스크의 완료율은 다음 방식으로 계산된다.

```text
진행률 = 완료된 서브태스크 수 / 전체 서브태스크 수 * 100
```

전체 서브태스크가 완료되면 부모 과제 상태도 `done`으로 동기화된다.

### 4.2 일정 관리

일정 관리 기능은 일정 추가, 목록 조회, 오늘 일정 조회, 기간별 일정 조회, 일정 삭제, D-day 계산을 제공한다.
일정은 `class`, `exam`, `personal`, `meeting`, `other` 카테고리로 구분된다.
사용자는 "내일 9시에 자료구조 수업 추가해줘."처럼 자연어로 말할 수 있고, Agent는 현재 날짜를 기준으로 절대 날짜를 계산한다.

### 4.3 공지사항 RAG 검색

공지 검색은 학과 공지와 학교 대표 공지를 구분한다.
학과 공지는 인하공업전문대학 컴퓨터시스템공학과 홈페이지를 대상으로 하며, 학교 대표 공지는 대표 홈페이지 공지 게시판을 대상으로 한다.

공지 검색 흐름은 다음과 같다.

1. 사용자가 공지 검색 요청을 입력한다.
2. Agent가 학과 공지 또는 학교 공지 도구를 선택한다.
3. 저장된 ChromaDB 데이터에서 관련 결과를 먼저 검색한다.
4. 결과가 부족하면 학교 홈페이지를 실시간 크롤링한다.
5. 수집한 공지를 청킹하고 ChromaDB에 저장한다.
6. 관련 공지 제목, 날짜, 카테고리, 요약, URL을 응답한다.

이 방식은 저장된 데이터의 빠른 검색과 실시간 정보 보강을 함께 활용한다.

### 4.4 대학생 정보 검색

대학생 정보 검색은 편입학, 전공심화, 국가장학금, 청년정책, 공모전, 대외활동, 현장실습, 인턴십 정보를 대상으로 한다.
구현된 도구는 다음과 같다.

| 도구 | 역할 |
|---|---|
| `search_student_info` | 저장된 대학생 정보에서 의미 기반 검색. |
| `search_personalized_student_info` | 전공, 학년, 관심 영역, 희망 진로를 반영한 추천. |
| `search_student_info_live` | 학교 대표 홈페이지 공지를 카테고리 키워드로 실시간 검색. |
| `search_transfer_by_school` | 특정 학교 편입학 모집요강 확인 경로 안내. |
| `search_scholarship_policy` | 온통청년 API 기반 청년정책 및 장학금 검색. |
| `search_job_intern` | 워크넷 API 기반 채용공고 및 인턴십 검색. |
| `search_contest_external` | K-스타트업 기반 창업지원 및 공모전 정보 검색. |
| `load_student_info_data` | 샘플 데이터 로드. |

이 기능은 학생이 놓치기 쉬운 외부 정보를 한 곳에서 탐색할 수 있게 한다.
다만 청년 정책의 실제 신청 가능 여부는 사용자 조건과 정책별 세부 조건에 따라 달라지므로, 결과는 확정 추천이 아니라 확인이 필요한 후보로 다루어야 한다.

### 4.5 장기기억

CampusAgent는 LangGraph의 `MemorySaver`와 SQLite 기반 장기기억을 함께 사용한다.
`MemorySaver`는 앱 실행 중의 단기 대화 문맥을 유지하고, SQLite는 앱 재실행 이후에도 남아야 하는 대화 메시지를 저장한다.

구현된 기능은 다음과 같다.

- 대화 세션 생성 및 조회.
- 사용자와 assistant 메시지 저장.
- 최근 대화 메시지 복원.
- 메모리 요약 저장 및 조회를 위한 테이블과 함수.
- 대화 기록 초기화.

현재 자동 요약 생성 트리거는 완성 범위에 포함하지 않았다.
따라서 장기기억은 대화 원문 저장과 최근 메시지 복원 중심으로 구현되었으며, 자동 요약 기반 개인화는 향후 개선 항목으로 남긴다.

2. 부모 과제와 5~7개의 서브태스크가 생성되는지 확인한다.
3. 과제 대시보드에서 일부 서브태스크를 완료 처리한다.
4. 부모 과제 진행률이 자동으로 반영되는지 확인한다.
5. "이번 주 마감 과제 알려줘."를 입력해 과제 조회가 정상 동작하는지 확인한다.
6. "학과 장학금 공지 찾아줘."를 입력해 공지 검색 결과를 확인한다.
7. "오늘 일정 알려줘." 또는 "다음 주 일정 보여줘."를 입력해 일정 도구를 확인한다.

## 7. 한계점

### 7.1 청년 정책 추천의 한계

공공 API와 공공 웹사이트에서 가져오는 정책 정보는 사용자의 실제 신청 가능 여부를 바로 확정하기 어렵다.
신청 가능 여부는 나이, 거주 지역, 소득, 취업 상태, 재학 상태, 신청 기간 등 다양한 조건에 따라 달라진다.
현재 시스템은 이 조건을 모두 구조화해 판정하지 않으므로, 청년 정책 검색 결과는 "신청 가능한 정책 확정"이 아니라 "확인해볼 정책 후보"로 보아야 한다.

### 7.2 외부 사이트 의존성

공지 크롤링과 외부 정보 검색은 원격 웹사이트의 HTML 구조, API 상태, 네트워크 상태에 영향을 받는다.
사이트 구조가 바뀌거나 API 키가 없으면 일부 기능이 제한될 수 있다.

### 7.3 ChromaDB 컬렉션 경계

현재 공지사항과 대학생 정보 검색 데이터가 같은 ChromaDB 컬렉션을 공유한다.
metadata로 구분하고 있지만, 장기적으로는 공지사항과 학생 정보 컬렉션을 분리하는 것이 더 안정적이다.

### 7.4 자동 요약 메모리 미완성

대화 원문 저장과 최근 메시지 복원은 구현되었지만, 오래된 대화를 자동 요약해 장기기억으로 압축하는 기능은 아직 완성되지 않았다.
최종 결과에서는 자동 요약 기반 개인화가 아니라 저장·복원 기반 장기기억으로 설명해야 한다.

### 7.5 Multi-Agent 구조 제외

초기 계획에서는 12주차에 Supervisor와 specialist를 나누는 Multi-Agent 구조를 고려했다.
하지만 일정 변경에 따라 12주차부터는 기존 프로그램 보완과 최종 발표, 최종보고서 준비로 전환했다.
따라서 Multi-Agent 구조는 구현 범위가 아니라 향후 개선 방향으로 남긴다.

---

## 8. 향후 개선 방향

향후 개선 방향은 다음과 같다.

1. 공지사항과 학생 정보용 ChromaDB 컬렉션을 분리한다.
2. 청년 정책 추천을 위해 사용자 프로필에 나이, 거주 지역, 취업 상태, 소득 구간 같은 조건을 추가한다.
3. 온통청년 API 결과의 자격 조건 필드를 구조화해 조건 기반 reranking을 도입한다.
4. 일정 시간이 지나거나 메시지가 일정 수 이상 누적되면 자동으로 대화를 요약해 `memory_summaries`에 저장한다.
5. Supervisor, Task specialist, Calendar specialist, Notice specialist, Info specialist로 나누는 Multi-Agent 구조를 실험한다.
6. Streamlit `app.py`를 UI 컴포넌트별 파일로 분리해 유지보수성을 높인다.
7. 실제 사용자 시나리오 기반 평가 데이터를 만들어 검색 품질과 추천 품질을 정량 평가한다.

## 9. 결론

본 프로젝트에서는 대학생의 학업 관리와 정보 탐색을 돕는 로컬 AI 학생 비서 CampusAgent를 구현했다.
CampusAgent는 LangGraph 기반 Agent, LangChain Tool, SQLite, ChromaDB, Streamlit, 웹 크롤링, 공공 API를 결합하여 자연어 요청을 실제 작업으로 연결한다.

구현 결과 사용자는 하나의 대화형 인터페이스에서 과제와 일정을 관리하고, 학교 공지를 검색하고, 대학생에게 필요한 외부 정보를 탐색할 수 있다.
특히 과제 자동 분해 기능은 단순한 과제 등록을 넘어 실행 가능한 작업 계획으로 변환한다는 점에서 학습 관리 도구로서 의미가 있다.

다만 외부 공공 정보 검색은 데이터 품질과 사용자 조건 부족이라는 한계가 있으므로, 최종 시스템에서는 확정 판정보다 후보 탐색과 원문 확인 보조에 초점을 둔다.
향후 사용자 프로필 확장, 정책 조건 구조화, 검색 저장소 분리, 자동 요약 메모리, Multi-Agent 구조를 보완하면 더 정교한 개인화 학생 비서로 발전할 수 있다.
