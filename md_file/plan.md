# CampusAgent 9~15주차 개발 계획 정리

작성 기준일: 2026-05-09  
프로젝트 단계: 15주 진행 중 10주차  
기준 자료: 8주차 중간발표 PPT, 9주차 실습일지, 현재 CampusAgent 프로젝트 분석 결과

## 1. 현재 상황 정리

CampusAgent는 대학생의 과제, 일정, 공지사항 확인을 하나의 대화형 인터페이스에서 처리하는 로컬 AI 어시스턴트이다. 현재 프로젝트는 Streamlit UI, LangGraph Agent, LangChain Tool 기반 도구, SQLite, ChromaDB, 실시간 공지 크롤러를 중심으로 구성되어 있다.

8주차 중간발표 기준으로는 과제 관리, 일정 관리, 학교/학과 공지 검색, 4-Tabs UI, Gemini/OpenAI 연동, 세션 내 대화 기억 기능이 구현된 상태로 정리되었다. 이후 9주차 실습일지에는 장기기억 문제 해결 내용이 작성되어 있지만, 실제 프로젝트 구현은 아직 진행하지 못한 상태이다.

따라서 앞으로의 계획은 다음 전제를 기준으로 다시 정리한다.

- 9주차 실습일지는 장기기억 구현 방향과 결과를 먼저 문서화한 상태이다.
- 실제 코드에는 아직 9주차 장기기억 기능이 반영되지 않았다.
- 10주차에는 9주차 실습일지 내용을 실제 프로젝트에 반영하면서, 동시에 대학생 통합 정보 검색 기능의 1차 구현까지 진행하는 방향으로 잡는다.
- 11~15주차는 정보 수집 범위 확장, 개인화 추천, 테스트, 최종 발표 준비를 단계적으로 진행한다.

## 2. 9주차 실습일지 파악 결과

9주차 실습일지의 주제는 **장기기억 문제 해결 및 대화 세션 복원 기능 구현**이다. 문서에서는 8주차까지의 한계였던 `MemorySaver` 기반 세션 기억 문제를 해결하기 위해 SQLite 기반 장기기억 구조를 도입한 것으로 정리되어 있다.

9주차 실습일지에 작성된 핵심 내용은 다음과 같다.

### 2.1 8주차까지의 한계

기존 CampusAgent는 LangGraph `MemorySaver`를 사용하여 실행 중인 세션에서는 대화 맥락을 유지할 수 있었다. 하지만 앱을 재시작하면 이전 대화 내역이 사라지고, 사용자가 다시 전공, 학년, 과제 맥락, 공지 검색 이력을 설명해야 하는 문제가 있었다.

실습일지에서 정의한 문제는 다음과 같다.

- `MemorySaver`는 세션 내부 기억만 유지한다.
- 앱 재시작 시 대화 이력이 초기화된다.
- 사용자의 반복 관심사나 학습 맥락을 장기적으로 활용하기 어렵다.
- 긴 대화가 누적되면 LLM에 전달되는 토큰 부담이 커진다.
- Streamlit 세션 상태와 LangGraph 메모리 사이의 일관성이 깨질 수 있다.

### 2.2 9주차 구현 목표

9주차 실습일지는 다음 구현 목표를 제시하고 있다.

1. 대화 메시지를 SQLite에 영구 저장한다.
2. 앱 재실행 후에도 이전 대화 이력을 불러올 수 있게 한다.
3. 모든 대화 원문을 계속 LLM에 넣지 않고 요약 메모리를 함께 관리한다.
4. LangGraph의 세션 기억과 DB의 장기기억을 함께 사용할 수 있도록 흐름을 정리한다.
5. 장기기억 기능이 기존 과제, 일정, RAG 기능을 방해하지 않도록 통합한다.

### 2.3 9주차 실습일지의 설계 내용

실습일지에서는 기존 `campus_tasks.db`에 장기기억 전용 테이블을 추가하는 구조를 제안한다.

| 테이블 | 목적 |
|---|---|
| `conversation_sessions` | 대화 세션 단위 정보 저장 |
| `conversation_messages` | 사용자/AI/tool 메시지 원문 저장 |
| `memory_summaries` | 긴 대화를 압축한 요약 메모리 저장 |

문서상 흐름은 다음과 같다.

1. 사용자가 메시지를 입력한다.
2. Streamlit 세션 메시지에 추가한다.
3. `conversation_messages`에 user 메시지를 저장한다.
4. LangGraph Agent를 실행한다.
5. AI 응답을 생성한다.
6. Streamlit 세션 메시지에 assistant 응답을 추가한다.
7. `conversation_messages`에 assistant 메시지를 저장한다.
8. 앱 재실행 시 DB에서 최근 세션과 메시지를 불러와 채팅창을 복원한다.

### 2.4 요약 메모리 구조

실습일지에서는 모든 대화 원문을 계속 LLM에 전달하는 대신, 최근 대화는 원문으로 유지하고 오래된 대화는 요약하여 `memory_summaries`에 저장하는 구조를 제안한다.

이 구조의 목적은 다음과 같다.

- 앱 재시작 후에도 이전 대화 맥락 유지
- 토큰 사용량 감소
- 과제, 일정, 공지 검색 흐름의 연속성 확보
- 사용자 전공, 학년, 관심사 기반 개인화 응답 강화

### 2.5 실제 프로젝트 반영 상태

현재 코드 기준으로는 9주차 실습일지에 적힌 장기기억 기능이 아직 반영되어 있지 않다. `database/db.py`에는 `assignments`, `schedules`, `user_settings` 테이블만 생성되고 있으며, `conversation_sessions`, `conversation_messages`, `memory_summaries` 테이블은 아직 없다.

또한 `agent/graph.py`는 여전히 LangGraph `MemorySaver`를 사용하고 있고, Streamlit 앱의 대화 이력은 `st.session_state.messages` 중심으로 관리된다.

따라서 9주차 내용은 “완료된 기능”이 아니라 **10주차에 실제 구현으로 이어받아야 할 선행 문서/설계 내용**으로 보는 것이 정확하다.

## 3. 8주차 향후 계획 수정 방향

8주차 PPT의 향후 계획은 현재 상황에 맞게 다음처럼 수정한다.

| 기존 계획 | 수정 방향 | 현재 반영 방식 |
|---|---|---|
| 크롤러 범위 제한 | 대학생 정보 수집원 확장 | 편입학, 국가 제도, 공모전/대외활동 정보까지 확장 |
| 장기 기억 없음 | 9주차 실습일지 기반으로 10주차 실제 구현 | 문서상 설계는 완료, 실제 코드는 10주차에 반영 |
| MCP 프로토콜 미준수 | 최종 필수 구현이 아닌 구조 개선 후보 | 기능 완성도와 발표 안정성을 우선 |
| 테스트 커버리지 부족 | 12~15주차 기능별 테스트와 데모 검증으로 보강 | 장기기억, 정보검색, 일정 연동 중심 테스트 추가 |

특히 장기기억은 9주차 보고서에서 이미 다룬 핵심 주제이므로, 10주차 초반에 실제 코드로 반영하고 이후 정보 검색 확장 기능과 연결하는 방식이 가장 자연스럽다.

## 4. 10~15주차 주차별 구현 계획

### 10주차: 9주차 장기기억 실제 반영 + 대학생 정보 검색 1차 구현

10주차는 단순히 계획을 정리하는 주차가 아니라, 9주차 실습일지에 작성한 장기기억 기능을 실제 프로젝트에 반영하고, 대학생 통합 정보 검색 기능의 1차 결과물을 만드는 주차로 진행한다.

구현 내용:

- SQLite에 `conversation_sessions`, `conversation_messages`, `memory_summaries` 테이블 추가
- 사용자 메시지와 AI 응답을 DB에 저장하는 함수 구현
- 앱 실행 시 최근 대화 내역을 불러와 `st.session_state.messages`에 복원
- 최근 대화 원문과 요약 메모리를 함께 활용할 수 있는 기본 구조 마련
- 기존 공지사항 RAG 구조를 참고해 `편입학`, `국가제도`, `공모전/대외활동` 카테고리를 담을 수 있는 데이터 구조 추가
- 샘플 데이터 또는 1차 수집 데이터를 기반으로 ChromaDB에 대학생 정보 문서 저장
- “편입학 정보 알려줘”, “국가장학금 제도 찾아줘”, “공모전 추천해줘” 같은 질문에 검색 결과가 나오도록 1차 도구 확장

10주차 결과물:

- SQLite 기반 장기기억 테이블 및 대화 저장/복원 흐름
- 앱 재시작 후 최근 대화 복원 확인
- 대학생 정보 검색 도구 1차 버전
- 편입학/국가제도/공모전 카테고리별 검색 응답 예시
- ChromaDB 저장 및 검색 확인

완료 기준:

- 앱을 껐다 켜도 최근 대화가 복원된다.
- 최소 3개 정보 카테고리에서 각각 2건 이상 검색 가능한 데이터가 있다.
- 자연어 질문으로 카테고리별 결과가 반환된다.
- 검색 결과에 제목, 요약, 출처, 마감일 후보가 포함된다.

### 11주차: 편입학 및 전공심화 정보 수집 고도화

11주차는 10주차에 만든 통합 정보 검색 구조 중 편입학 영역을 집중적으로 고도화한다.

구현 내용:

- 우리학교 전공심화 과정 및 진학 관련 정보 수집
- 타학교 편입학 모집요강 정보 수집 대상 선정
- 학교명, 모집 단위, 지원 자격, 제출 서류, 전형 일정, 원서 접수 기간을 구조화
- 편입학 관련 질문에 학교별 비교 응답 제공
- 편입학 마감일을 캘린더 또는 과제 등록 후보로 추출

11주차 결과물:

- 편입학 전용 검색 기능
- 우리학교/타학교 편입학 정보 비교 응답
- 주요 일정 및 제출 서류 요약

완료 기준:

- 우리학교 및 타학교 편입학/전공심화 정보가 함께 검색된다.
- 사용자가 학교명이나 전공명을 포함해 질문했을 때 관련 결과가 우선 표시된다.
- 마감일이 있는 정보는 후속 등록 안내가 제공된다.

### 12주차: 국가 제도 정보 수집 기능 구현

12주차는 대학생이 자주 확인해야 하는 국가 지원 제도를 CampusAgent가 검색하고 요약할 수 있게 만드는 단계이다.

구현 내용:

- 국가장학금, 국가근로장학금, 학자금대출, 청년정책 정보 수집
- 신청 대상, 신청 기간, 지원 내용, 필요 서류, 공식 출처 정리
- 사용자가 “내가 신청할 수 있는 제도”를 물었을 때 전공/학년 정보를 활용해 추천
- 신청 기간이 있는 제도는 캘린더 등록 후보로 안내
- 9주차 장기기억 구조를 활용해 사용자가 자주 찾는 제도 정보를 이후 추천에 반영

12주차 결과물:

- 국가 제도 검색 기능
- 제도별 신청 조건 요약 응답
- 신청 기간 기반 일정 등록 후보 생성
- 장기기억 기반 관심 제도 재추천 흐름

완료 기준:

- 국가장학금, 국가근로장학금, 학자금대출 관련 검색 응답이 가능하다.
- 공식 출처 URL 또는 출처명이 응답에 포함된다.
- 사용자의 학년/상황을 반영한 추천 문장이 포함된다.

### 13주차: 공모전/대외활동 정보 수집 기능 구현

13주차는 공모전, 대외활동, 현장실습, 인턴십 정보를 추가하여 CampusAgent가 학생의 진로와 활동 기회까지 도와줄 수 있게 만든다.

구현 내용:

- 공모전/대외활동/현장실습/인턴십 정보 수집 구조 추가
- 분야, 주최기관, 대상, 접수 기간, 마감일, 지원 링크를 중심으로 구조화
- 전공과 관심 분야 기반 추천 응답 작성
- 마감 임박 활동 우선 표시
- 공모전 마감일을 과제 또는 캘린더로 등록하는 흐름 설계

13주차 결과물:

- 공모전/대외활동 추천 기능
- 마감 임박 정보 안내
- 전공 기반 활동 추천 응답

완료 기준:

- “소프트웨어 공모전”, “대외활동”, “인턴십” 질문에 구분된 결과가 반환된다.
- 마감일이 있는 항목은 D-day 또는 마감 임박 안내가 가능하다.
- 사용자가 관심 분야를 말하면 관련 정보가 우선 표시된다.

### 14주차: 개인화 추천 및 일정 연동 강화

14주차는 9~13주차에 추가한 장기기억과 정보 검색 기능을 기존 과제/일정 기능과 연결하여 실제 개인 비서처럼 동작하도록 만드는 단계이다.

구현 내용:

- 사용자 전공, 학년, 관심 분야를 검색 결과 랭킹에 반영
- 장기기억에 저장된 이전 검색 관심사를 추천에 활용
- 검색 결과에서 날짜, 마감일, 신청 기간을 추출
- “이 정보를 캘린더에 등록할까요?”, “마감 과제로 추가할까요?” 같은 후속 액션 제공
- 사용자가 원할 경우 대화 기록 초기화 또는 요약 메모리 초기화 기능 제공

14주차 결과물:

- 개인화 추천 응답
- 검색 결과 기반 일정/과제 등록 흐름
- 장기기억 기반 관심 정보 추천
- 대화 기록 관리 기능 1차 버전

완료 기준:

- 같은 정보라도 사용자 전공/학년에 따라 추천 문장이 달라진다.
- 마감일이 있는 검색 결과에서 일정/과제 등록 후보가 생성된다.
- 최근 관심 분야를 기반으로 관련 정보를 다시 추천할 수 있다.

### 15주차: 최종 통합 테스트 및 발표 준비

15주차는 구현된 기능을 통합 검증하고 최종 발표 자료와 시연 흐름을 완성하는 단계이다.

구현 내용:

- 과제, 일정, 공지, 장기기억, 편입학, 국가제도, 공모전 검색 흐름을 하나의 데모 시나리오로 구성
- 핵심 기능별 정상 동작 테스트
- 예외 상황 테스트: 검색 결과 없음, 날짜 추출 실패, API 키 없음, 크롤링 실패, 대화 복원 실패
- 최종 발표 PPT 보완
- 시연 영상 또는 라이브 데모용 질문 리스트 작성

15주차 결과물:

- 최종 통합 테스트 결과
- 최종 발표 PPT 보완본
- 시연 시나리오
- 최종 데모 질문 목록

완료 기준:

- 앱 재시작 후 대화 복원 시나리오가 시연 가능하다.
- 주요 기능이 하나의 사용자 흐름으로 자연스럽게 연결된다.
- 발표 중 보여줄 질문과 기대 응답이 준비된다.
- 기능 실패 시에도 사용자에게 이해 가능한 안내 메시지가 출력된다.

## 5. 추천 추가 계획

### 5.1 정보 출처와 수집일 표시

편입학, 국가 제도, 장학금, 공모전 정보는 정확성과 최신성이 중요하다. 검색 결과마다 공식 출처 URL, 수집일, 정보 유형을 표시해야 한다.

추천 표시 형식:

- 공식 출처: 학교 입학처, 한국장학재단, 정부/공공기관
- 참고 출처: 공모전 플랫폼, 대외활동 사이트, 일반 안내 페이지
- 수집일: 정보가 언제 수집되었는지 표시

### 5.2 마감일 자동 추출 및 일정 연동

편입학 원서 접수, 장학금 신청, 공모전 마감일은 사용자가 놓치면 손해가 크다. 따라서 검색 결과에서 날짜를 추출하고, 바로 캘린더나 과제로 등록할 수 있게 연결한다.

예상 흐름:

1. 사용자가 “국가장학금 신청 기간 알려줘”라고 질문한다.
2. CampusAgent가 신청 기간과 마감일을 요약한다.
3. “마감일을 캘린더에 등록할까요?”라고 후속 행동을 제안한다.
4. 사용자가 동의하면 일정 또는 과제로 저장한다.

### 5.3 장기기억 기반 추천

9주차 실습일지의 장기기억 설계를 실제 구현한 뒤에는 사용자의 반복 관심사를 추천에 활용할 수 있다.

예시:

- 사용자가 편입학 정보를 자주 검색하면 편입학 일정과 모집요강을 우선 추천
- 장학금 정보를 반복 검색하면 국가장학금, 교내장학금, 국가근로 정보를 함께 추천
- 공모전 정보를 자주 검색하면 전공 관련 공모전과 마감 임박 대외활동을 우선 추천

### 5.4 발표용 데모 시나리오 강화

최종 발표에서는 기능을 나열하기보다 한 학생의 실제 사용 흐름처럼 보여주는 것이 효과적이다.

추천 시나리오:

1. “지난번에 이야기한 과제 내용 기억해?”
2. “이번 주 마감인 과제 알려줘”
3. “오늘 일정 보여줘”
4. “우리학교 전공심화 정보 알려줘”
5. “국가장학금 신청 기간 알려줘”
6. “소프트웨어 공모전 추천해줘”
7. “방금 찾은 공모전 마감일 캘린더에 등록해줘”

이 흐름은 9주차 장기기억, 기존 과제/일정 관리, 10주차 이후 정보 검색 확장을 모두 보여줄 수 있다.

## 7. 기대 결과

이 계획이 완료되면 CampusAgent는 기존의 “과제, 일정, 공지사항 관리 AI”에서 “사용자의 대화 맥락을 기억하고 대학생에게 필요한 정보를 통합적으로 찾아주는 캠퍼스 생활 AI”로 발전한다.

최종적으로 기대되는 모습은 다음과 같다.

- 앱을 다시 실행해도 이전 대화 맥락을 이어갈 수 있다.
- 학생이 직접 여러 사이트를 돌아다니지 않아도 필요한 정보를 한 대화창에서 확인할 수 있다.
- 편입학, 장학금, 국가 제도, 공모전 등 중요한 정보를 놓치지 않도록 지원한다.
- 검색 결과를 단순히 보여주는 데서 끝나지 않고 일정/과제 등록으로 연결한다.
- 전공, 학년, 이전 관심사를 기반으로 개인화된 추천을 제공한다.
- 최종 발표에서 실제 사용 가능한 캠퍼스 AI 서비스로 설득력 있게 시연할 수 있다.

정리하면, 9주차 실습일지는 장기기억 기능의 방향과 기대 결과를 먼저 작성한 문서이고, 실제 구현은 10주차부터 진행해야 한다. 따라서 10주차는 9주차 장기기억 내용을 코드에 반영하는 작업과 대학생 통합 정보 검색 1차 구현을 함께 진행하는 핵심 전환 주차로 설정한다.
